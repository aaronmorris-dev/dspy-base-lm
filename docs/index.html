Gate 00 · Decision

Choose the shortest honest path.

A custom LM is not the default. First decide what the workload needs, then prove that normal dspy.LM cannot reach the model without losing behavior.

Write the workload brief

Custom-LM decision sequence

  1. Can current dspy.LM address the model through a supported provider?
  2. Does a documented OpenAI-compatible endpoint preserve every required feature?
  3. Can configuration alone select the endpoint and model?
  4. Does the model require a custom SDK, wire protocol, CLI, subscription session, or local runtime?

Build an LMProvider only when the fourth answer identifies a real missing seam.

Gate 03 · Contract design

Map one typed boundary.

LMRequest enters the provider and LMResponse leaves it. Runtime transport details never become a second framework.

Response and error maps

Preserve when applicable

  • One LMOutput per candidate
  • Text, thinking, tools, citations, refusals, media
  • Finish reason, truncation, log probabilities
  • LMUsage, cost, response ID, safe metadata

Map known failures

  • Transport, auth, billing, rate limit
  • Invalid request and context overflow
  • Unsupported model, timeout, server error
  • Unknown boundary failure → chained LMUnexpectedError

Runtime and cache boundary

Clients, credentials, sessions, connections, and subprocess handles stay on the provider. Persistent extensions and metadata must be finite, JSON-like values without credential-shaped keys or reference cycles.

If native response data contains a runtime object, cycle, or credential-shaped key, the live response is returned but deliberately not cached.

Gate 04 · Implementation

Build one vertical slice.

Begin with text-only sync and async. Add capabilities only after the previous slice passes natively and through DSPy.

Run EchoLM first

import dspy
from dspy_base_lm import EchoLM

lm = EchoLM(model="echo/reference", cache=False)
request = dspy.LMRequest.from_call(model=lm.model, prompt="Hello typed DSPy")
response = lm(request)
assert isinstance(response, dspy.LMResponse)
assert response.text == "Hello typed DSPy"

Provider anatomy

class MyProvider(LMProvider):
    def __init__(self, client: MySDKClient) -> None:
        super().__init__()
        self.client = client

    def supported_params(self, model: str) -> frozenset[str]:
        return frozenset({"temperature", "max_tokens"})

    def supports_function_calling(self, model: str) -> bool:
        return model == "my-provider/tool-model"

    def complete(self, request: dspy.LMRequest, *, num_retries: int) -> dspy.LMResponse:
        native_request = to_native_request(request)
        native = self.client.generate(native_request, retries=num_retries)
        return to_lm_response(native, model=request.model)

    async def acomplete(self, request: dspy.LMRequest, *, num_retries: int) -> dspy.LMResponse:
        native_request = to_native_request(request)
        native = await self.client.agenerate(native_request, retries=num_retries)
        return to_lm_response(native, model=request.model)

Injection or inference?

Inject a provider

Use when the application owns a live client or authenticated session. It is intentionally runtime-only and must be reattached after load.

Subclass infer_provider

Use when safe ambient configuration can reconstruct the provider. EchoLM demonstrates this explicit path.

Gate 05 · Integration

Prove behavior through DSPy.

A native provider smoke test is necessary, but it does not prove that adapters, caching, history, or usage retain the same meaning.

Public-behavior ledger

Current upstream boundaries

  • Typed custom-LM streaming: blocked by DSPy 3.3 public integration.
  • Provider launch/kill and reinforcement: upstream signatures name concrete dspy.LM.
  • BootstrapFinetune per-LM mappings may exclude custom BaseLM instances.
  • No compatibility wrapper is added to make these features appear supported.

Completion criterion
